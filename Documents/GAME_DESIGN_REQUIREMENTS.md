## 1. 卡包积分

### 1.1 按卡包尺寸确定基础分

状态：`已确认`

每种卡包尺寸对应一个基础分。

- 卡包尺寸由 `Resources/Configs/CardPacks.csv` 中的 `PackSize` 配置。
- `PackSize` 使用 `CardPackSize` 数值，范围为 `XS=1` 到 `XXXL=7`。
- 基础分映射由 `GameScoreUtility` 管理。

| 卡包尺寸 | 基础分 |
|---|---:|
| XS | 60 |
| S | 80 |
| M | 100 |
| L | 120 |
| XL | 140 |
| 2XL | 160 |
| 3XL | 200 |

### 1.2 积分计算时机

状态：`已确认`

- 当前拼图完成后，在游戏结算期间计算积分。
- 积分计算属于 GameScene 结算流程。

### 1.3 未使用提示加成

状态：`已确认`

- 记录玩家在当前拼图游戏中是否使用过提示功能。
- 玩家未使用提示完成游戏时，结算增加卡包基础分的 5%。
- 只要使用过至少一次提示，就不应用该 5% 加成。
- 点击 `BtnTips` 时，从当前组选择 Piece 编号最小的未完成碎片作为提示目标；只有存在有效目标并成功启动提示时才记为使用提示。
- 目标碎片在托盘原位置短暂左右抖动数次后停止并恢复原旋转，不持续无限抖动。
- 棋盘对应槽位显示绿色滚动虚线轮廓；虚线根据目标 Piece Sprite 的实际 Alpha 像素边界，沿真实轮廓累计长度生成等长线段，不为单个卡包制作提示蒙版。
- `BtnTips` 第一次点击显示提示，提示存在时再次点击取消；一旦成功显示过提示，本局仍视为已使用提示。
- 目标碎片成功放置、切换分组、进入结算或离开场景时停止抖动并清除虚线。

### 卡包拍照

- 只有历史上至少完整完成过一次、生命周期为 `Completed` 的卡包在选择面板显示拍照按钮。
- 新拆开但尚未完整完成的卡包不显示拍照按钮，即使已经保存了部分拼图进度。
- 点击拍照按钮后先播放一次全屏白色闪光，再生成 `1024 x 1024` PNG。
- 照片由统一木纹底图、当前卡包完整拼图和游戏 Logo 合成，不要求每个卡包制作独立拍照底图。
- 文件以 `游戏名-YYYY-MM-DD-BagId.png` 保存到桌面，BagId 使用三位编号；同日同一卡包重复拍照覆盖同名文件。
- 保存成功后显示位于选中卡包之上的照片预览面板；预览期间隐藏选中卡包，点击 OK 后恢复卡包并返回选择页。

| 卡包尺寸 | 基础分 | 未使用提示时的分数 |
|---|---:|---:|
| XS | 60 | 63 |
| S | 80 | 84 |
| M | 100 | 105 |
| L | 120 | 126 |
| XL | 140 | 147 |
| 2XL | 160 | 168 |
| 3XL | 200 | 210 |

### 1.4 关闭关卡描边加成

状态：`已确认`

- 记录当前拼图游戏中是否启用过关卡描边。
- 玩家未启用关卡描边完成游戏时，结算额外增加 2%。
- 当前游戏中启用过关卡描边时，不应用该 2% 加成。

### 1.5 关闭贴纸描边加成

状态：`已确认`

- 记录当前拼图游戏中是否启用过贴纸描边。
- 玩家未启用贴纸描边完成游戏时，结算额外增加 5%。
- 当前游戏中启用过贴纸描边时，不应用该 5% 加成。
- 此规则与关闭关卡描边的 2% 加成相互独立。

### 1.6 完成时间加成

状态：`已确认`

- 记录当前拼图游戏的耗时，并在结算时计算时间加成。
- 第一个拼图 Piece 成功放置时开始计时；放置失败不启动计时。
- 完成拼图并开始 RewardPanel 结算流程时停止计时。
- 三个时间阈值可配置，后续继续调优。
- 初始阈值：

| 参数 | 初始值 |
|---|---:|
| A | 15 秒 |
| B | 30 秒 |
| C | 60 秒 |

| 完成时间 | 时间加成 |
|---|---:|
| 时间 `<= A` | +3% |
| 时间 `> A` 且 `<= B` | +2% |
| 时间 `> B` 且 `<= C` | +1% |
| 时间 `> C` | 无时间加成 |

### 1.7 最终积分公式

状态：`已确认`

- 卡包尺寸决定 `BaseScore`。
- 将当前游戏符合条件的所有百分比加成相加。
- `BaseScore` 乘以 1 加总加成比例。
- 结果向上取整到下一个整数。

```text
TotalBonusRate = NoHintBonus
               + LevelOutlineDisabledBonus
               + StickerOutlineDisabledBonus
               + CompletionTimeBonus

FinalScore = Ceil(BaseScore * (1 + TotalBonusRate))
```

示例：M 卡包的 `BaseScore=100`。如果同时满足未使用提示 `+5%`、关闭关卡描边 `+2%`、关闭贴纸描边 `+5%` 和最快时间档 `+3%`：

```text
TotalBonusRate = 5% + 2% + 5% + 3% = 15%
FinalScore = Ceil(100 * 1.15) = 115
```

### 1.8 结算积分表现

状态：`已确认`

结算分数必须分阶段展示，不能直接显示最终值：

1. 先显示卡包基础分。
2. 展示一项符合条件的加成。
3. 将显示分数动画滚动到该阶段的累计分数。
4. 对每项符合条件的加成重复展示和分数滚动。
5. 最后一次滚动停在 `FinalScore`。

每次分数滚动动画期间：

- 进度条和进度值必须持续刷新。
- 结算页面显示的分数必须同时滚动。
- 两处显示必须使用相同的动画分数值，并同时结束。
- 播放表现前，积分计算应产出基础分、符合条件的加成项、累计阶段分数和最终分数；UI 代码只负责展示结果。

### 1.9 待确认的积分细节

状态：`待确认`

- 符合条件的加成项展示顺序。
- 每次分数滚动的时长、缓动和最小视觉步长。
- 中间累计分数是否也向上取整，还是只对 `FinalScore` 取整。
- 同一局先打开再关闭关卡描边是否失去加成资格；当前文字记录为“当前游戏中从未启用”。

## 2. 卡包生命周期

状态：`已确认`

每个卡包有一个持久化生命周期状态：

| 状态 | 含义 |
|---|---|
| `Locked` | 卡包尚未发放，不显示在 MainScene。 |
| `Unlocked` | 卡包已发放，但尚未完成第一组拼图。开包后在第一组完成前退出，仍保持此状态。 |
| `InProgress` | 尚未历史完成，且已经进入 GameScene 开始拼图。 |
| `Completed` | 卡包中的所有拼图分组均已完成。 |

生命周期转换：

1. 发放卡包时，`Locked` 变为 `Unlocked`。
2. 首次进入 GameScene 时，`Unlocked` 变为 `InProgress`。
3. 每个正确放置的 Piece 由独立拼图会话即时记录，不依赖生命周期表达具体进度。
4. 完成最后一组后，状态变为 `Completed`。
5. 正常游戏和重玩中，`InProgress` 和 `Completed` 不降级；重玩进度由独立会话记录，不能把 `Completed` 降级。

MainScene 的展示和排序必须使用该生命周期状态。

### MainScene 卡包选择操作

状态：`已确认`

- 只有生命周期为 `Completed` 且不存在当前拼图会话时，确认按钮显示 `重玩`。
- `Unlocked`、`InProgress`，以及存在未完成重玩会话的 `Completed` 卡包，确认按钮统一显示 `玩`。
- `Locked` 卡包不在 MainScene 列表中显示，因此不能进入选择面板。
- 点击 `玩` 直接继续现有流程；点击 `重玩` 时先显示 `PanelReplay` 确认弹窗，不直接开包。
- `PanelReplay/BtnReplay` 确认并复用现有开包舞台和进入 GameScene 的流程；`BtnReturn` 与 `BtnClose` 取消并返回卡包选择页。
- 确认重玩时清除该卡包的旧拼图会话；进入 GameScene 后创建新会话。
- `PanelReplay` 显示期间，选中卡包和其他列表卡包不得绘制在弹窗上方；取消后恢复，确认后保持隐藏并衔接开包舞台。
- 相机按钮只对 `Completed` 卡包显示，并执行上文“卡包拍照”中定义的闪光、保存和预览流程。

### 拼图进度保存

状态：`已确认`

- 每个卡包最多存在一条当前拼图会话；会话与历史生命周期分开存储。
- 进入 GameScene 即创建会话，因此尚未正确放置 Piece 时退出也属于可继续的一局。
- Piece 正确吸附到棋盘后，立即按 `PieceNN` 完整数字编号保存；只持久化已正确放置 Piece，不保存托盘或桌面 Piece 的位置。
- 再次进入时，已保存 Piece 直接显示在棋盘原槽位，并从首个未全部完成的分组继续创建剩余 Piece。
- 整包完成并成功保存 `Completed` 后删除当前会话；下次选择该卡包才重新显示 `重玩`。

### MainScene 卡包排序

状态：`已确认`

首个版本不包含每日挑战卡包。MainScene 使用以下顺序：

1. 自上一次 MainScene 列表展示后新发放的卡包。这些卡包只优先展示一次；同时发放多个时，最新发放的在前。
2. `InProgress` 卡包。
3. `Unlocked` 卡包，按解锁时间从早到晚。
4. `Completed` 卡包，按首次完成时间从早到晚。

MainScene 消费新发卡包的临时优先级后，它们恢复为正常生命周期优先级。重启应用也会清除此临时优先级。时间戳相同或无效时，按 PackId 升序作为确定性并列规则。未来每日挑战实现会将相应卡包插入到这些优先级之前。

## 3. 卡包获取

状态：除明确列出的待确认参数外，其余均为 `已确认`。

新卡包有两个获取来源：

1. 完成任务必定创建一条新卡包权益。
2. 首次完成一个卡包时，执行一次受阶段门槛控制的发包尝试。

重玩规则：

- 重玩已经 `Completed` 的卡包不执行首次完成发包尝试。
- 重玩仍可完成任务；完成任务时正常发放任务必得卡包奖励。
- 从 `Unlocked` 或 `InProgress` 首次转换为 `Completed` 时，具备阶段门槛发包资格。

“新卡包”指当前状态为 `Locked` 的卡包；两个来源都不会重复发放已经解锁的卡包。

两个来源均从当前内部章节中符合条件的 `Locked` 卡包池选择。

待确认参数：

- 从符合条件的 `Locked` 卡包中选择时的最终规则和顺序。
- 没有符合条件的 `Locked` 卡包时的处理方式。
- 根据试玩结果，是否需要在某个阶段重新引入概率判定。

当前试玩实现：

- `TaskConfig.csv` 配置 6 个随机任务模板，覆盖累计分数、收集贴纸、完成卡包三种类型，以及任意尺寸和随机指定尺寸两种筛选方式。
- 随机任务按模板权重选择，并避免连续选择同一个模板；指定尺寸只从玩家当前可玩的卡包尺寸中选择。
- 积分任务目标按 `200、400、600、800、1000、1200` 固定循环，不做纯随机；贴纸目标从 `60、80、100` 中随机，完成卡包目标从 `1、2、3` 中随机。
- 三类任务均在符合尺寸要求的卡包完整结算时累计；重玩同样计入。贴纸任务一次累计当前卡包的全部贴纸数。
- 初期（`R >= 9`）：`H <= 5` 时允许发包，发放后最多 `H=6`。
- 中期后段过渡点（`R = 8`）：`H <= 3` 时允许发一个包，发放后最多 `H=4`。
- 中期后段剩余阶段（`R = 7..3`）：仅 `H <= 2` 时允许发包，发放后最多 `H=3`。
- 末期（`R = 2..1`）：`H <= 1` 时允许发包，发放后最多 `H=2`。
- 被拦截的首次完成发包直接跳过。被拦截的任务奖励持久化为待发，在之后首次完成或任务完成后重试，永不丢弃。
- 待发任务奖励按唯一 `TaskInstanceId` 标识，任务推进保存失败时不会重复加入同一任务奖励；重复出现同一模板不会被误判为旧奖励。
- 新加入队列的任务奖励只有在任务推进持久化成功后才发放；推进失败时，权益保留在队列等待重试。
- 待发任务奖励先于当前首次完成发包尝试。
- 同一轮结算中，任务和首次完成来源都通过阶段门槛时，可以发放两个不同卡包。
- 在当前章节内，锁定候选按 `Index` 升序选择。任务配置的 `RewardId` 只有在仍为锁定状态且属于该章节时才优先。
- RewardPanel 保留编辑器设置的默认 `ImgBag` 图标，不替换为发放卡包封面。点击 `BtnFinish` 时，本次结算发放的全部卡包从 `ImgBag` 一起飞到居中行，停顿并跨越 MainScene 加载，再分别飞到对应卡包列表位置。

## 4. 内部章节模型

状态：除每章准确分配和转换参数外，其余均为 `已确认`。

- 游戏使用 8 个内部章节组织卡包数据并控制发放。
- 完整游戏计划约 150 个卡包。
- 每个内部章节约 18 个卡包，数学平均值为每章 18.75 个。
- 章节不向玩家展示。MainScene 不显示章节名、章节编号、章节选择或章节切换提示。
- 当前内部章节限制任务奖励和首次完成发包使用的卡包池。

章节阶段计数：

- `R` 是当前章节尚未发放、仍为 `Locked` 的卡包数量。
- 持有可玩卡包数包括 `Unlocked` 和 `InProgress`，不包括 `Completed`。
- 标准 18 包章节在初始卡包发放后从 `R=17` 开始。较大章节额外的 `R` 值属于初期。

| 章节阶段 | `R` 范围 | 持有可玩卡包目标 |
|---|---:|---|
| 初期 | 17 降至 9 | 增长到约 5-6 个。 |
| 中期后段 | 8 降至 3 | 逐步降到约 2-3 个。 |
| 末期 | 2 降至 1 | 内部章节推进前收敛到 1 个。 |

待确认参数：

- 每章准确卡包数量及 PackId 成员。
- 初始当前章节及持久化章节进度数据。
- 推进到下一内部章节的准确条件。
- 特殊卡包如何计入约 150 总量和章节分配。
- 任务节奏和首次完成发包如何维持已确认的阶段目标。

## 5. 拼图分组表现

状态：`已确认`

### 托盘自动补位

- 创建当前组时按 Piece 编号从左向右布局。
- 成功放置 Piece 后，仅编号位于其后的 Piece 沿 X 轴向前补位；前序 Piece 以及所有剩余 Piece 的 Y 和缩放不得刷新。
- 先放置队尾 Piece 时，其他 Piece 不执行任何位置刷新。
- 补位后的 X 坐标只作为 Piece 仍在托盘时的位置；Piece 一旦从托盘放到桌面，不再返回该位置。
- 最后一个 Piece 拿起时继续执行托盘退出，成功后直接进入切组或结算流程。

### 桌面放置

- Piece 未命中正确槽位时，只有贴图渲染边界完全位于 CardBag 棋盘范围外，才停留在松手位置。
- 未命中正确槽位且贴图边界与棋盘相交时自动恢复到本次拖拽起点；从托盘拿起时恢复托盘位置和尺寸，从桌面拿起时恢复原桌面位置。
- 桌面 Piece 保持棋盘目标缩放，并可再次拿起、移动或吸附到正确槽位。
- Piece 必须完整限制在游戏背景可见范围内，不能被拖出屏幕。
- Piece 首次离开托盘时按现有规则补位后序托盘 Piece；已经位于桌面的 Piece 不参与托盘计数、布局或补位。
- 未吸附松手前，已退出的空托盘恢复到原位，继续作为桌面 Piece 的回收目标。
- Piece 与托盘水平方向有交集且垂直进入托盘达到自身当前高度的 `50%` 时，松手后恢复托盘尺寸并与其他托盘 Piece 按编号自动排列；低于 `50%` 时继续停留桌面。
- 正确槽位吸附优先于托盘回收判定。

### 棋盘配置缩放

- `Resources/Configs/CardPacks.csv` 使用正数 `BoardScale` 配置每个卡包的棋盘缩放比。
- 进入 GameScene 后，当前 `CardBagNNN` 的棋盘、Piece 槽位、描边坐标和吸附坐标统一使用该比例。
- Piece 初始位于下方黑色托盘时，生成比例取“配置后的棋盘目标比例”和“原黑色托盘规则算出的比例”中的较小值，不按整组是否超框分支。
- 玩家拿起 Piece 时使用配置后的棋盘目标比例，因此按下后只能保持尺寸或放大，不能缩小；未正确吸附时以该比例停留在桌面。
- Piece 成功吸附后必须立即改用 CardBag Prefab 中对应的原始 `Image` 显示，不继续保留世界空间 `SpriteRenderer`；已放置 Piece 与棋盘共同继承 `BoardScale`，接缝不得随缩放比增大。

### 分阶段描边边界

- 第 1 组只显示自身边界中属于最终拼图外边界的部分。
- 后续每组显示自身最终拼图外边界，以及与所有已完成低编号组的接触边。
- 当前组不得显示已完成组的无关边界。
- 当前组不得显示与未来组的接触边。
- 同组内各 Piece 之间的接缝不得显示。
- 同一描边像素只能由最早需要它的阶段显示；后续组不得重复显示前序组已经画过的最终外边界，避免接触边在组交界处向已完成区域延伸。
- 组间接触边和最终外轮廓的阶段归属必须同时满足距离与边界法线方向；仅在边界切线方向靠近当前组时不得延长描边端点。
- 最终外轮廓与已完成组接触边在交汇处不得强行连接；两类线段分别在对方边界 `24px` 范围外结束，防止交汇端点伸入已完成贴纸或空白区域。
- 运行时只显示当前组的烘焙描边图，不叠加之前阶段的图片。
- 描边烘焙属于编辑器内容制作步骤；缺少生成数据不得阻止拼图交互。

## 6. 卡包打开表现

状态：`已确认`

- MainScene 列表和选中放大统一使用对应 PackId 的 `PackIconNNN.png` 静态封面，不加载 3D 模型、Animator 或粒子。

- 点击 MainScene 卡包后，将静态封面从列表实际位置移动到屏幕中心，同时在 `0.3s` 内等比放大到 `600 x 680`，并显示 `PanelBagSelect`。
- 点击 `PanelBagSelect/BtnPlay` 或确认重玩后，首页内容退场并切换到与 GameScene 同源的 `BgGame` 开包舞台；除放大的选中卡包外，其他列表卡包和尺寸图标隐藏。
- 卡包定场后等待玩家再次轻点卡包或横划。撕包动画暂未接入，有效操作当前直接进入 GameScene；后续实现动画时必须保留该输入和场景切换边界。
- GameScene 必须延续同一背景，棋盘从上方、碎片托盘从下方进入，当前组 Piece 错峰落入托盘；入场期间屏蔽拼图操作。
- GameScene 加载或首帧资源初始化即使发生短暂卡顿，也不得跳过棋盘滑入和 Piece 飘落过程。
- 点击 `PanelBagSelect/BtnBack` 后隐藏面板，将静态封面反向移动并缩放回原列表位置。
- 列表静态封面、阴影与尺寸图标归属同一卡包槽位；当前不播放呼吸动画。
- 每个尺寸图标只作为所属卡包的前景层，不得跨越并遮挡其他卡包；选择状态的视觉层级固定为选中卡包最高、`PanelBagSelect` 次之、其他列表卡包最低。
- `PanelBagSelect` 打开时，其他列表卡包不得隐藏；面板半透明背景需要将它们明显压暗，同时仍能辨认卡包内容。
- 闭合状态的 3D 第一帧替换点击的 2D 封面时，不得出现可见的位置、尺寸、比例、裁切或空白边变化。

- 通用模型或动画无法加载时，MainScene 保留现有 2D 回退交互。
